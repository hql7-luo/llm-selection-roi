# 外贸业务团队该用哪个大模型？值不值得用？

[English](README.md) · **中文** · [交互式 ROI 计算器](https://hql7-luo.github.io/llm-selection-roi/) · [方法说明（英文）](docs/methodology.md)

一家做印刷耗材和包装出口的中国小公司，每月通过邮件、阿里巴巴和聊天工具收到约 500 封询盘。现在是业务员一封封看、手动登记到跟进表，再决定先回哪封。设想是：让大模型先生成登记草稿（产品、规格、数量、目标价、贸易条款、目的地、交期、缺失信息、优先级），业务员再核对。

两个问题：**该用哪个模型？到底值不值得花这笔钱？** 项目用 100 份带标准答案的询盘、一套评分代码、一个真实跑过的"不用 AI"规则基线、当天的 API 价格，加一个简单的 ROI 模型来回答。公司和所有询盘都是虚构的。

## 目前的结论

**选模型要看它在你们自己询盘上的准确率，而不是看价格。** 在基准假设下，只要出现关键错误的询盘少于约 **17%**，"AI 草稿 + 人工核对"就划算。不用 AI 的规则方法没过这条线（测试集上 **20%**）。各个大模型的实测还没跑（见[模型结果](#模型结果)）。

- **模型价格几乎不影响结论。** 按标价估算，API 成本是**每千份询盘 $0.04 到 $6.18**；而 AI 草稿每千份能省约 **$728 的人工**。从最便宜的模型换到最贵的，盈亏平衡点只移动 **0.07 个百分点**。
- **准确率影响很大。** 每月 500 封询盘时，关键错误率每高 1 个百分点，每月多花约 **$42**（改错的时间，加上流到客户那里的错误）。而最便宜和最贵模型之间的价差，每月只有约 **$3**。贵的模型只要把关键错误率降低约 0.1 个百分点，就值回差价。
- **只靠规则不够。** 关键词加正则的方法能填对 93% 的字段，但测试集里 20% 的询盘至少错了一个关键字段（规整询盘 10%，难题 55%）。每月 500 封时约**亏 $125**。
- **影响最大的是人工核对这一步。** 如果核对能发现 95% 的 AI 错误（基准是 80%），可接受的错误率从 17% 升到 58%；如果只能发现 60%，就降到 9%。

## 怎么做的

- **数据集：** 60 份常规询盘（阿里巴巴 RFQ 表单、短邮件、聊天消息，其中 8 份俄语），25 份手写难题，15 份陷阱（垃圾邮件、钓鱼、收费诈骗、我们不卖的产品）。20 份用来调提示词和规则，80 份锁定只做最终测试。
- **关键错误：** 产品、规格、数量、目标价或交期有错，凭空多出一个产品，或者把高优先级询盘排低了。另外还统计字段准确率、加权错误、编造信息的比例、优先级混淆矩阵、JSON 格式失败率、多次运行的一致率、成本和速度。
- **每封询盘的 ROI：** 省下的人工，减去 API 成本，再减去比纯人工多出来的错误损失（人也会出错）。月度结果包含每月维护费；一次性搭建成本用来算回本时间。

详细说明见 [methodology（英文）](docs/methodology.md)。

## 局限

- **还没有测任何大模型。** 成本和盈亏平衡线是实的；某个模型能不能过线，要等测试跑完才知道。
- **数据是合成的。** 询盘和标准答案是在 AI（Claude）帮助下为这个项目写的，参照常见的印刷耗材外贸询盘。参测模型里也有 Claude，可能对它有利。真要做决定前，应该拿 50 到 100 封真实（脱敏）询盘重新标注。
- **规则基线的成绩可能偏乐观。** 规则和数据是同一个作者写的，真实邮箱会更乱。
- **人工和错误损失是假设值。** 最关键的几项（核对发现率、错误流出去的损失、人工错误率）应该实测：手动计时处理 10 封询盘，第一个月统计核对时发现了多少 AI 错误。
- **价格会变。** OpenAI、DeepSeek、Qwen 的价格来自第三方汇总，使用前请看官方页面。跑之前 token 数是估算的。会先"思考"再回答的模型可能用多得多的输出 token；即使最贵的模型输出量是估算的 10 倍，盈亏平衡点也只从 17.0% 变到 16.6%。
- 数据隐私、在国内能否访问、付款方式，对中国出口企业是真实的选型因素，但这里没有打分。
