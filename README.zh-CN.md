# 外贸业务团队该用哪个大模型？值不值得用？

[English](README.md) · **中文** · [交互式 ROI 计算器](https://hql7-luo.github.io/llm-selection-roi/) · [方法说明（英文）](docs/methodology.md)

一家做印刷耗材和包装出口的中国小公司，每月通过邮件、阿里巴巴和聊天工具收到约 500 封询盘。现在是业务员一封封看、手动登记到跟进表，再决定先回哪封。设想是：让大模型先生成登记草稿（产品、规格、数量、目标价、贸易条款、目的地、交期、缺失信息、优先级），业务员再核对。

两个问题：**该用哪个模型？到底值不值得花这笔钱？** 项目用 100 份带标准答案的询盘、一套评分代码、一个不用 AI 的规则基线、三个真实测过的 Claude 模型、当天的 API 价格、公开榜单分数，加一个简单的 ROI 模型来回答。公司和所有询盘都是虚构的。

## 结论

**用能通过你们自己询盘测试的最便宜模型。在这套测试里，就是 Claude Haiku 5.5。** 在基准假设下，只要出现关键错误的询盘少于约 **17%**，"AI 草稿 + 人工核对"就划算。三个 Claude 模型都远低于这条线，规则方法没过线。

- **测试的模型几乎全对。** 80 份测试询盘各跑 2 遍，Claude Haiku 5.5 和 Claude Opus 5.5 **没有**关键错误，Claude Sonnet 5.5 在 160 次里错了 1 次（0.6%）。不用 AI 的规则方法有 **20%** 的询盘出现关键错误（难题里是 55%）。
- **回本很快。** 每月 500 封询盘时，用 Haiku 扣掉 API、核对和出错成本后每月约省 **$714**，$2,000 的搭建成本约 **2.8 个月**收回。只用规则则每月约亏 $125。
- **价格几乎不重要，准确率才重要。** 按标价，API 成本是每千份 **$0.04 到 $6.18**，而 AI 草稿每千份能省约 **$728 人工**。关键错误率每高 1 个百分点，每月多花约 **$42**；最便宜和最贵模型之间的价差每月只有约 **$3**。Opus 比 Haiku 贵 40 倍，在这里没有带来更高准确率。
- **公开榜单没能预测这个任务。** 在 Artificial Analysis 综合榜上，Opus 58 分、Haiku 43 分，差距很大；但在这种范围窄、规则清楚的信息抽取任务上，差距消失了。综合榜考的是难推理，这份工作用不到。
- **这些分数要当作上限看。** 测试询盘是在 Claude 帮助下写的，又拿 Claude 模型来测，真实询盘会更乱。真要做决定前，应该拿 50 到 100 封真实（脱敏）询盘再测一次。

**Claude 模型怎么测的。** 没有用 API key。三个模型在构建环境里以 Claude 子代理的方式运行：每个子代理拿到一批 20 份询盘和与 API 版相同的指令，只允许打开这一个批次文件（每个都只读了一次文件），每份询盘回一行 JSON。每个模型把 80 份测试询盘跑 2 遍。原始回答保存在 [`runs/`](runs)。因为没有调用 API，所以没有 token 数和响应时间，成本按标价估算。

**为什么其他模型没测。** 构建环境只能连 Anthropic 的服务器，OpenAI、DeepSeek、阿里云都被拦截。它们只列出标价和公开榜单分数，runner 已经准备好（见[通过 API 重跑](#通过-api-重跑)）。

**唯一的错误。** 有一封俄语询盘写的是"термальные пластины CTP"（热敏 CTP 版），但没给尺寸和厚度。Sonnet 有一次把"thermal"填成了规格。标准答案是"没有规格"，因为没有尺寸和厚度就没法报价；不过 Sonnet 的理解也说得通。第二遍时它和标准答案一致。

## 怎么做的

- **数据集：** 60 份常规询盘（阿里巴巴 RFQ 表单、短邮件、聊天消息，其中 8 份俄语），25 份手写难题，15 份陷阱（垃圾邮件、钓鱼、收费诈骗、我们不卖的产品）。20 份用来调提示词和规则，80 份锁定只做最终测试。
- **关键错误：** 产品、规格、数量、目标价或交期有错，凭空多出一个产品，或者把高优先级询盘排低了。另外还统计字段准确率、加权错误、编造信息的比例、优先级混淆矩阵、JSON 格式失败率和两遍结果的一致率。
- **每封询盘的 ROI：** 省下的人工，减去 API 成本，再减去比纯人工多出来的错误损失（人也会出错）。月度结果包含每月维护费；一次性搭建成本用来算回本时间。

详细说明见 [methodology（英文）](docs/methodology.md)。

## 运行

```bash
pip install -r requirements.txt
python build_dataset.py      # 重新生成 data/（每次结果相同）
python run_eval.py rules     # 规则基线，不花钱
python run_analysis.py       # 给所有结果打分，生成 results/、figures/ 和 docs/roi-data.js
pytest                       # 检查数据、评分、规则、runner、ROI，以及 Python 和网页结果一致
```

### 通过 API 重跑

想用正常方式测某个模型（每次一封询盘、temperature 0、有真实 token 数），设置 key 后运行：

```bash
export DEEPSEEK_API_KEY=...             # 或 ANTHROPIC_API_KEY、OPENAI_API_KEY、DASHSCOPE_API_KEY
python run_eval.py deepseek:deepseek-flash --split dev --runs 1   # 先用 20 份试一下
python run_eval.py deepseek:deepseek-flash --runs 3               # 正式跑
python run_analysis.py
```

按标价，8 个模型各跑 3 遍总共约 $3.30。如果模型不在 [`data/pricing.csv`](data/pricing.csv) 里，先加一行价格。用 API 重跑 Claude 模型会替换掉子代理的结果。

## 局限

- **数据是合成的，而且有 Claude 参与编写。** 询盘和标准答案是在 AI（Claude）帮助下为这个项目写的，参照常见的印刷耗材外贸询盘。Claude 模型几乎满分，可能部分来自这一点，分数应当作上限。
- **Claude 的测试不是 API 测试。** 子代理一次处理 20 份，带有代理自己的系统提示和默认设置，走 API 的结果可能略有不同。成本是估算，不是实测。
- **只测了一家厂商。** GPT、DeepSeek、Qwen 只比较了价格和公开榜单，没有比准确率。对中国出口企业来说，国内能否访问、数据隐私和付款方式也很重要，这里没有打分。
- **规则基线的成绩可能偏乐观。** 规则和数据是同一个作者写的，真实邮箱会更乱。
- **人工和错误损失是假设值。** 最关键的几项（核对发现率、错误流出去的损失、人工错误率）应该实测：手动计时处理 10 封询盘，第一个月统计核对时发现了多少 AI 错误。
- **价格会变。** OpenAI、DeepSeek、Qwen 的价格来自第三方汇总，使用前请看官方页面。
